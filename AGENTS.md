# AGENTS.md

Nextflow executor plugin for robotic wet-lab steps (prototype). Design, concerns and plan live in the control-panel repo: `/home/vangelis/Documents/10_Projects/Seqera/Nextflow Robotics` (https://github.com/vagkaratzas/nextflow-robotics, private). Read its `AGENTS.md` and `docs/DESIGN.md` first; record findings and decisions there, not here.

- **Build:** `make assemble`, `make test`, `make install` (installs into `~/.nextflow/plugins`). Targets Nextflow 26.10.0 (`build.gradle`).
- **Adapter (`adapter/`):** Python 3.12 via `uv` (`~/.local/bin/uv`), not base conda. `cd adapter && uv sync`, then `uv run pytest`; serve with `uv run uvicorn nf_lab_adapter.app:main --factory` (ledger file: `$NF_LAB_LEDGER`, default `ledger.sqlite`; backend: `NF_LAB_BACKEND=fake` (default, scripted) or `plr` (PyLabRobot simulation, protocol `plate_transfer`; `NF_LAB_VISUALIZER=1` serves its browser view of the deck at http://127.0.0.1:1337 from adapter startup); seconds per simulated step: `NF_LAB_STEP`). `labctl` (`src/nf_lab_adapter/labctl.py`, stdlib only) is the adapter's CLI client, the wet task's script: `uv run labctl run --help` (a job = one plate: `--plate P1 --wells A1:S01 D2:NC1:negative_control ...`); it writes `labctl.log`, `provenance.json` and `result.json` into `--outdir` (default: the work dir); adapter URL from `--adapter` or `$NF_LAB_ADAPTER` (default `http://127.0.0.1:8000`). The ledger has no migrations: after a schema change, delete old ledger files (the adapter refuses ones from before the plate map). After changing the API, regenerate the contract: `uv run python -m nf_lab_adapter.app > openapi.json` (a test fails if it drifts). Add deps with `uv add` (dev: `uv add --dev`).
- **End-to-end checks (`validation/`):** the success criteria, one `checks/<name>/.checks` each (Nextflow `tests/checks` style). `make install`, `cd adapter && uv sync`, then `validation/run.sh [name ...]` with `nextflow` on PATH; each check starts its own FakeBackend adapter on a free port and runs in `build/validation/<name>` (`checks.out` there on failure).
- **CI (`.github/workflows/ci.yml`):** job `test` (`make test`, adapter pytest, `validation/run.sh lint`) on every push; job `validation` (all checks) on PRs, `main` and manual runs: `gh workflow run CI --ref <branch>`. Nextflow 26.10.2 only.
- **Branches:** work on `dev`; `main` gets reviewed PRs from `dev` (Adam reviews, CI green). By agreement, not enforced: GitHub has no branch protection for private repos on the free plan; add the rules when the repo goes public. The owner may push to `main` directly.
- **Java:** builds use SDKMAN Java 17, the default `$JAVA_HOME`. Don't point `JAVA_HOME` at base conda: its Java is 1.7 and its `jre/` breaks Gradle's TLS download. All other tools come from base conda (`~/miniconda3/bin/<tool>`).
