# AGENTS.md

Nextflow executor plugin for robotic wet-lab steps (prototype). Start with README.md.

- **Build:** `make assemble`, `make test`, `make install` (installs into `~/.nextflow/plugins`). Targets Nextflow 26.10.0 (`build.gradle`).
- **Adapter (`adapter/`):** Python 3.12 via `uv`. `cd adapter && uv sync`, then `uv run pytest`; serve with `uv run uvicorn nf_lab_adapter.app:main --factory` (ledger file: `$NF_LAB_LEDGER`, default `ledger.sqlite`; backend: `NF_LAB_BACKEND=fake` (default, scripted) or `plr` (PyLabRobot simulation: `plate_transfer`, `plate_split`, `rna_extraction`, `dna_extraction` on liquid handlers, `plate_read` on `plate-reading` robots, `pcr` on `thermocycling` ones, `qpcr` (RT-qPCR, a Ct per well) on `qpcr` ones, and one protocol per other machine in `bindings.plr.MACHINES`: `plate_mix` (shaking), `plate_lysis` (heating-shaking), `heat_inactivation` (temperature-control), `plate_tilt` (tilting), `plate_spin` (centrifugation), `plate_incubate` (incubation), `reagent_dispense` (pumping), `plate_weigh` (weighing), `powder_dispense` (powder-dispensing), and on simulated backends of our own `plate_seal` (sealing), `plate_unseal` (peeling), `plate_scan` (barcode-reading); `NF_LAB_VISUALIZER=1` serves its browser view of the deck at http://127.0.0.1:1337 from adapter startup); seconds per simulated step: `NF_LAB_STEP`; robots in the pool: `NF_LAB_DEVICES` (default 1), or pools with queues `capability[/queue]:count,…`, e.g. `liquid-handling/opentrons:1,liquid-handling/hamilton:1` (a job with `labctl --queue`, from Nextflow's `queue` directive, runs only on its queue's robots); simulated operator, which unloads done plates and loads queued ones: `NF_LAB_SIMULATED_OPERATOR=1|0`, default 1 for fake, 0 for plr). Token: `NF_LAB_TOKEN` (unset: no check; set: every request needs `Authorization: Bearer`, `labctl` and the dashboard send it from their env, a pipeline from a Nextflow secret). Deck controls (the operator API, kept out of `openapi.json`): http://127.0.0.1:8000/deck, a row per robot with load + confirm deck, unload (= release), e-stop, and resolve a failed job (done, read off the deck, or void). A job runs only on a free robot that runs its protocol (the backend's `PROTOCOLS`) and holds its plate; submit refuses a protocol no robot of the capability runs. `labctl` never releases: on `done` it writes the outputs and exits 0. `labctl` (`src/nf_lab_adapter/labctl.py`, stdlib only) is the adapter's CLI client, the wet task's script: `uv run labctl run --help` (a job = one plate: `--plate P1 --wells A1:S01 D2:NC1:negative_control ...`); it writes `labctl.log`, `provenance.json` and `result.json` into `--outdir` (default: the work dir); adapter URL from `--adapter` or `$NF_LAB_ADAPTER` (default `http://127.0.0.1:8000`), `--poll`/`--grace` defaults from `$NF_LAB_POLL`/`$NF_LAB_GRACE`. In a pipeline these come from the plugin's `lab {}` config scope (`adapter`, `poll`, `grace`): the `lab` executor (`LabTaskHandler`) puts them in the wrapper's launch environment, not in the work dir or the task hash; an unset one falls back to the launch shell's env. The ledger has no migrations: after a schema change, bump `VERSION` in `ledger.py` and delete old ledger files (the adapter refuses other versions). After changing the API, regenerate the contract: `uv run python -m nf_lab_adapter.app > openapi.json` (a test fails if it drifts). Conformance kit (`adapter/conformance/`, only `pytest` + `jsonschema`): `uv run pytest conformance --adapter <url>` checks any adapter against `openapi.json` (it leaves its jobs in that adapter's ledger: use a test adapter that loads plates itself); without `--adapter` it starts the fake and plr adapters on free ports. Add deps with `uv add` (dev: `uv add --dev`).
- **Wet modules (`wet-modules/`):** Nextflow only: `modules/<protocol>/{main.nf, meta.yml, result.schema.json}` (one module per protocol; `meta.yml`'s `lab:` block names capability, protocol, version, stop boundary) and `subworkflows/`. Examples include them by relative path (`../../wet-modules/...`) and keep their own `bin/labctl` symlink. `adapter/tests/test_wet_modules.py` checks meta, script and schema agree and every binding's result fits its schema. nf-tests per module: `wet-modules/tests/run.sh` (fake adapter on :8190, needs `make install`). Sketch for a separate repo later (`git subtree split`); see `wet-modules/README.md`.
- **Dashboard (`dashboard/`):** live demo view (FastAPI + one static page, polls every second); its own `uv` project: `cd dashboard && uv sync`, `uv run pytest`, serve with `uv run uvicorn nf_lab_dashboard.app:main --factory --port 8080`. Read-only: reads `.nextflow.log`, the ledger (opened `mode=ro`), the adapter's request log `<ledger>.requests.jsonl` and `GET /devices`; never imports adapter code. Its demo bar (`demo.py`, `/api/demo`) runs scripted scenarios: starts its own adapter on :8000 with a fresh ledger in `build/demo/<example>/<scenario>/`, runs the example picked in the bar (`EXAMPLES`: plate_transfer has Pool, E-stop and Manual; plate_assay only Manual; parallel_extraction Side by side and Manual), plays the person through the operator API; tests use the fake backend and a stub pipeline. See `dashboard/README.md`.
- **End-to-end checks (`validation/`):** the success criteria, one `checks/<name>/.checks` each (Nextflow `tests/checks` style). `make install`, `cd adapter && uv sync`, then `validation/run.sh [name ...]` with `nextflow` on PATH; each check starts its own FakeBackend adapter on a free port and runs in `build/validation/<name>` (`checks.out` there on failure).
- **CI (`.github/workflows/ci.yml`):** job `test` (`make test`, adapter and dashboard pytest, `validation/run.sh lint`) on every push; job `validation` (all checks) on PRs, `main` and manual runs: `gh workflow run CI --ref <branch>`. Nextflow 26.10.2 only.
- **Branches:** work on `dev`; `main` gets reviewed PRs from `dev`, with CI green.
- **Java:** the plugin build needs Java 17.

## nf-lab adapter / dashboard dev
- Before starting the adapter or running e2e tests, check for stale processes and env vars: `lsof -i :8000 -i :8100` and `env | grep NF_LAB_ADAPTER`. Kill orphaned adapters and unset stale ports first.
- E2E timing assertions must use generous windows, because GitHub CI runners are much slower than local. Never assert sub-second timings.
- Work feature by feature: implement ONE plan item, test it, commit it, then stop and check in before the next.
- Don't add unrequested commits (helper notes, etc.).
